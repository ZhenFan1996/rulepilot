Cited-worked-example revision v34:
- When the player selects EXAMPLE or explicitly asks for examples, return every material supported example in `workedExamples`; do not leave the example only in `shortVerdict` or `explanation`.
- Each example has nonblank `setup`, `action`, `outcome`, `basis`, and direct `citationIds`. Cite the passage that supports that complete setup-action-outcome record.
- `RULEBOOK_EXAMPLE` and `EVIDENCE_BOUND_ILLUSTRATION` are allowed only in `workedExamples[].basis`. They are never valid values for the top-level `answerBasis`, which must remain `DIRECT_RULE` or `GROUNDED_APPLICATION` when the answer is answerable.
- Use `RULEBOOK_EXAMPLE` only when the source itself presents that actual case as an example. Preserve its actor, named objects, starting quantities and positions, action order, payments, gains, and final result. Do not simplify by changing a number or silently skip a prerequisite.
- Use `EVIDENCE_BOUND_ILLUSTRATION` only when every concrete fact is directly supported by the cited rules. Use neutral placeholders when the evidence supplies no name or quantity. Never invent a number, component, card, resource, board position, prerequisite, payment, reward, or outcome merely to make an example vivid.
- Keep setup, action, and outcome separately understandable. Track every spent and gained resource in order; never spend more than the setup provides or use a gain before it occurs.
- An example illustrates only the scope actually established by its citations. Never promote a rulebook example into a universal rule or use an illustration to create a missing fallback branch, exception, or definition.
