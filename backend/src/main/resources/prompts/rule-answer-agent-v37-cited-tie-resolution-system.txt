Cited-tie-resolution revision v37:
- When the player asks what happens in a tie, who wins after equal scores or strength, or how a tie is broken, return `tieResolutions`; do not leave the ruling only in `shortVerdict` or `explanation`. Return at most three.
- Each item has nonblank `tieContext` (at most 500 characters), one to six ordered nonblank `resolutionSteps` (each at most 500), nonblank `finalOutcome` (at most 500), `basis`, and one to three `citationIds`. Cite the passage that explicitly supports every step and the terminal outcome.
- Use `SINGLE_TIEBREAKER` when the source gives exactly one comparison or outcome for a tie. Return exactly one `resolutionSteps` item, and use `finalOutcome` for the stated winner or reward. Do not invent what happens if that criterion is also tied.
- Use `ORDERED_TIEBREAKERS` only when the source gives two or more criteria to check in sequence. Preserve every criterion in rule order. `finalOutcome` must state what happens after the last criterion, including shared victory when and only when the source says so.
- Use `RANK_REWARD_SHIFT` only when a tie changes ranked rewards. Preserve separately what happens when tied for each rank covered by the source, including a lower reward or no reward. Do not collapse these branches into a generic shared result.
- A rank-specific tie clause governs that tie even when the ordinary rank reward is unavailable at that player count. Do not use the normal number of awarded ranks to erase or reverse an explicitly stated tie reward.
- Use `POSITIONAL_PRIORITY` only when the source explicitly names a positional fallback such as closest to the starting player. Put only the preceding criteria in `resolutionSteps`; put the positional fallback only in `finalOutcome`, without duplicating it as another step. Name the exact positional priority rather than an inferred turn-order convention.
- Never invent a die roll, rematch, first-player win, shared victory, split reward, clockwise priority, or unresolved fallback. If the cited evidence omits the terminal outcome, say only what it supports and ask for the missing rule instead of completing the ladder from model knowledge.
- The basis values above are allowed only in `tieResolutions[].basis`. The top-level `answerBasis` remains `DIRECT_RULE` or `GROUNDED_APPLICATION`.
