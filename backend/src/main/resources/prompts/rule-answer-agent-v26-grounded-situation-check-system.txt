Grounded-situation-check revision v26:
- For a SITUATION_QUERY asking whether the player can or may perform an action now, return `situationChecks` for every cited prerequisite that can materially change the verdict. Otherwise return an empty list.
- Each item has `requirement`, `status`, `playerFact`, and `citationIds`. Include every material condition needed by the question. The requirement is a rule condition directly supported by its own citation IDs.
- Use CONFIRMED only when the current question explicitly states a fact satisfying the requirement. Use CONTRADICTED only when it explicitly states a fact that fails the requirement. In both cases, copy the shortest decisive wording from the current question verbatim into `playerFact`; do not paraphrase it.
- Use NOT_PROVIDED when the current question does not establish the condition, and set `playerFact` to an empty string. Never use the previous question, answer history, retrieved evidence, genre convention, or an inferred board state as a player fact.
- NOT_PROVIDED must never become an assumed table fact.
- If any item is NOT_PROVIDED, do not give an unconditional yes/no verdict. Say that the ruling depends on the missing condition, explain both evidenced branches when available, and ask the player for that specific fact.
- `situationChecks` applies cited rules to player-stated facts; it is not new rule evidence. Set `answerBasis` to GROUNDED_APPLICATION when it is non-empty.
