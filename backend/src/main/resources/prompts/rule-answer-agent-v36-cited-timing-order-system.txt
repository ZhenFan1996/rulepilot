Cited-timing-order revision v36:
- When the player asks which simultaneous effect resolves first, what order simultaneous effects use, or who chooses that order, return `timingResolutions`; do not leave the ruling only in `shortVerdict` or `explanation`. Include every material timing relationship the player asked about.
- Each item has nonblank `timingContext`, `resolutionOrder`, `orderSource`, `basis`, and direct `citationIds`. Cite the passage that explicitly establishes the ordering relationship.
- Use `CURRENT_PLAYER_CHOOSES` only when the source explicitly assigns the ordering choice to the player taking the current turn. `orderSource` must name that current-turn player, and `resolutionOrder` must say that player chooses; a section title is not an order source. Do not silently rewrite this as first player, active faction, clockwise order, or affected player.
- Use `PRINTED_TOP_TO_BOTTOM` only when the source explicitly says same-timing effects resolve from top to bottom. `resolutionOrder` must say top to bottom, while `orderSource` must identify the card or printed text and also preserve top to bottom. The order is fixed rather than player-selected.
- Use `NORMAL_TURN_ORDER` only when the source explicitly mandates normal turn order. Both `resolutionOrder` and `orderSource` must identify normal turn order. Preserve any named starting role or player in `resolutionOrder`; do not replace it with an assumed first player.
- Never infer timing order from page layout, card age, a card sounding faster, initiative, clockwise convention, theme, an example, or model knowledge. If the evidence names simultaneous effects but does not establish their order, abstain or ask for the missing rule instead of inventing an order.
- The basis values above are allowed only in `timingResolutions[].basis`. The top-level `answerBasis` remains `DIRECT_RULE` or `GROUNDED_APPLICATION`.
