Source coverage contract revision v18:
- Return `sourceCoverageInventoryComplete` and `sourceCoverageSlots` in addition to the ordinary outline fields. This
  is a source inventory made before chapter prose is written; it is not a confidence score and it cannot be completed
  by adding generic chapter labels.
- `sourceCoverageSlots` is an array of objects with exactly `slotId`, `role`, `sourceIdentifier`,
  `sourcePageNumbers`, `ownerTopicKey`, and `availability`. Use a unique short ASCII kebab-case slotId. Copy one exact,
  contiguous, source-language heading, action name, rule opening, or external-source title of at most 160 characters
  into sourceIdentifier. The identical sourceIdentifier must appear as one retrievalQueries item in the owner topic,
  and every slot page must appear in that topic's sourcePageNumbers.
- Use only these roles: SETUP, CORE_LOOP, LEGAL_ACTION, ENDING, SCORING, NECESSARY_EXCEPTION, and SUPPORTING_RULE.
  Create at least one slot for SETUP, CORE_LOOP, ENDING, and SCORING. Create a separate LEGAL_ACTION slot for every
  distinct ordinary action or mutually exclusive action branch the supplied rules make available. Create a separate
  NECESSARY_EXCEPTION slot for every sourced exception, restriction, override, player-count branch, or timing clause
  that a first-game player needs to apply another required slot correctly. SUPPORTING_RULE is only for another
  source-owned rule group that is useful but is not one of those six playable roles.
- Classify from the active document's relationships, never from a title dictionary, familiar component name, page
  number, or board-game convention. A phase heading is not automatically a legal action, and an example is not an
  exception unless the source says it changes or limits the governing rule.
- Use SOURCED only when the supplied page directly contains that slot's relation. Use MISSING_EXTERNAL_SOURCE only
  when a supplied page explicitly names another unavailable source and explicitly assigns it setup, core loop,
  ending, or scoring responsibility; bind the referring page and exact external title. Do not use
  MISSING_EXTERNAL_SOURCE for an ordinary retrieval failure. UNRESOLVED is reserved for a deliberately incomplete
  inventory and therefore cannot appear when sourceCoverageInventoryComplete is true.
- Give every sourced slot exactly one ownerTopicKey. The owner must be required for SETUP, CORE_LOOP, LEGAL_ACTION,
  ENDING, SCORING, and NECESSARY_EXCEPTION. Its coverageTags must contain setup, core_loop, legal_action, end,
  scoring, or necessary_exception respectively. A SUPPORTING_RULE owner uses source_coverage. A missing external
  source belongs only to its source_dependency topic and keeps the corresponding missing_*_source marker. For every
  non-dependency owner topic, retrievalQueries must contain exactly the distinct sourceIdentifier values of its owned
  slots, with no broad extra question; this lets the immutable plan retain every required action and exception.
- For a visual page catalog whose `sourceRuleGroupIdentifiers` inventory is complete, map every listed identifier to
  exactly one SOURCED slot on that same page, including every separately listed action and exception. Do not merge a
  later rule group into a broad core-loop slot or omit it because the four core labels already appear.
- Set sourceCoverageInventoryComplete true only after auditing every substantive supplied page, every legal action,
  every necessary exception, and the four core roles, and after checking that no source identifier has conflicting
  chapter owners. Missing external sources may be represented honestly, but they remain unavailable and can never
  make the eventual lesson complete.
