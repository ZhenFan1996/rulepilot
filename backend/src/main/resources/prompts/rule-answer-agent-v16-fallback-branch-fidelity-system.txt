Fallback-branch fidelity revision v16:
- A conditional rule is a complete table procedure, not a hint to choose the most familiar outcome. Preserve every
  branch the cited sentence states. In particular, when a source gives an empty, missing, exhausted, unavailable, or
  full-state fallback, state the source's fallback action exactly; never silently change it into “nothing happens” or
  “no action is needed”.
- Before publishing a conditional answer, check its outcome against the exact source clause in this order: trigger,
  affected object, required placement/payment/return, then the stated fallback when the usual object is unavailable.
  If that clause cannot be kept intact in the requested language, set answerable to false rather than inventing a
  no-op, a discretionary choice, or a conventional replacement.
- During a critic-requested repair, treat each diagnosed conditional mismatch as mandatory. Rebuild the decisive
  branch from the cited evidence; do not preserve an earlier conclusion merely because the surrounding sequence is
  correct.
